# 库存专题

> 面试高频度：⭐⭐⭐⭐⭐
> 适用场景：电商系统、秒杀系统、订单系统、仓储系统
> 核心难点：高并发扣减、超卖问题、数据一致性

## 一、库存扣减方案对比

### 1.1 方案概览

| 方案 | 实现方式 | 优点 | 缺点 | 适用场景 |
|------|----------|------|------|----------|
| 数据库悲观锁 | SELECT ... FOR UPDATE | 强一致性，实现简单 | 性能差，容易死锁 | 低并发场景 |
| 数据库乐观锁 | version 字段 CAS | 性能好，无锁 | 高并发时失败率高 | 中等并发 |
| Redis 预扣库存 | Lua 脚本原子操作 | 性能极好 | 需要额外维护 Redis | 高并发秒杀 |
| 消息队列异步 | 削峰填谷 | 削峰能力强 | 实时性差，实现复杂 | 超高并发 |
| 分布式锁 | Redis/Zookeeper | 强一致性 | 性能中等，有死锁风险 | 分布式系统 |

### 1.2 数据库悲观锁方案

```java
/**
 * 悲观锁扣减库存
 * 使用 SELECT ... FOR UPDATE 锁定行
 */
public class PessimisticLockInventory {
    
    /**
     * 扣减库存（悲观锁）
     *
     * @param productId 商品ID
     * @param quantity 扣减数量
     * @return 是否成功
     */
    public boolean deductStock(Long productId, Integer quantity) {
        Connection conn = null;
        try {
            conn = getConnection();
            conn.setAutoCommit(false);
            
            // 1. 查询库存（加悲观锁）
            String selectSql = "SELECT stock FROM inventory WHERE product_id = ? FOR UPDATE";
            PreparedStatement selectStmt = conn.prepareStatement(selectSql);
            selectStmt.setLong(1, productId);
            ResultSet rs = selectStmt.executeQuery();
            
            if (!rs.next()) {
                return false;
            }
            
            Integer currentStock = rs.getInt("stock");
            
            // 2. 校验库存
            if (currentStock < quantity) {
                conn.rollback();
                return false;
            }
            
            // 3. 扣减库存
            String updateSql = "UPDATE inventory SET stock = stock - ? WHERE product_id = ?";
            PreparedStatement updateStmt = conn.prepareStatement(updateSql);
            updateStmt.setInt(1, quantity);
            updateStmt.setLong(2, productId);
            updateStmt.executeUpdate();
            
            // 4. 提交事务
            conn.commit();
            return true;
            
        } catch (Exception e) {
            if (conn != null) {
                try {
                    conn.rollback();
                } catch (SQLException ex) {
                    ex.printStackTrace();
                }
            }
            return false;
        } finally {
            if (conn != null) {
                try {
                    conn.setAutoCommit(true);
                    conn.close();
                } catch (SQLException e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

**优点**：
- 强一致性，不会超卖
- 实现简单，易于理解

**缺点**：
- SELECT ... FOR UPDATE 会锁住整行，其他事务必须等待
- 高并发下性能极差
- 容易造成死锁

### 1.3 数据库乐观锁方案

```java
/**
 * 乐观锁扣减库存
 * 使用 version 字段实现 CAS
 */
public class OptimisticLockInventory {
    
    /**
     * 扣减库存（乐观锁）
     *
     * @param productId 商品ID
     * @param quantity 扣减数量
     * @return 是否成功
     */
    public boolean deductStock(Long productId, Integer quantity) {
        int maxRetries = 3;
        
        for (int i = 0; i < maxRetries; i++) {
            // 1. 查询当前库存和版本号
            String selectSql = "SELECT stock, version FROM inventory WHERE product_id = ?";
            // 执行查询，获取 currentStock 和 version
            
            Integer currentStock = getCurrentStock(productId);
            Integer version = getVersion(productId);
            
            // 2. 校验库存
            if (currentStock < quantity) {
                return false;
            }
            
            // 3. CAS 更新
            String updateSql = "UPDATE inventory SET stock = stock - ?, version = version + 1 " +
                             "WHERE product_id = ? AND version = ?";
            int rows = executeUpdate(updateSql, quantity, productId, version);
            
            // 4. 更新成功则返回
            if (rows > 0) {
                return true;
            }
            
            // 5. 更新失败，重试
        }
        
        return false;
    }
}
```

**优点**：
- 不加锁，性能好
- 适合中等并发场景

**缺点**：
- 高并发时重试次数多，失败率高
- 需要额外的 version 字段

### 1.4 Redis 预扣库存方案

```lua
-- Redis Lua 脚本：原子扣减库存
-- KEYS[1]: 库存 key
-- ARGV[1]: 扣减数量

local stock = tonumber(redis.call('GET', KEYS[1]))
if stock == nil then
    return -1  -- 库存不存在
end

if stock < tonumber(ARGV[1]) then
    return 0  -- 库存不足
end

redis.call('DECRBY', KEYS[1], ARGV[1])
return 1  -- 扣减成功
```

```java
/**
 * Redis 预扣库存方案
 * 适用于高并发秒杀场景
 */
public class RedisInventoryService {
    
    /** Redis 连接池 */
    private JedisPool jedisPool;
    
    /** Lua 脚本 SHA */
    private String deductScriptSha;
    
    /**
     * 初始化 Lua 脚本
     */
    public void init() {
        String script = 
            "local stock = tonumber(redis.call('GET', KEYS[1])) " +
            "if stock == nil then return -1 end " +
            "if stock < tonumber(ARGV[1]) then return 0 end " +
            "redis.call('DECRBY', KEYS[1], ARGV[1]) " +
            "return 1";
        
        try (Jedis jedis = jedisPool.getResource()) {
            deductScriptSha = jedis.scriptLoad(script);
        }
    }
    
    /**
     * 扣减库存（Redis Lua 原子操作）
     *
     * @param productId 商品ID
     * @param quantity 扣减数量
     * @return 扣减结果：1-成功，0-库存不足，-1-库存不存在
     */
    public Long deductStock(Long productId, Integer quantity) {
        String key = "inventory:" + productId;
        
        try (Jedis jedis = jedisPool.getResource()) {
            return (Long) jedis.evalsha(
                deductScriptSha,
                Collections.singletonList(key),
                Collections.singletonList(String.valueOf(quantity))
            );
        }
    }
    
    /**
     * 初始化库存
     *
     * @param productId 商品ID
     * @param stock 初始库存
     */
    public void initStock(Long productId, Integer stock) {
        String key = "inventory:" + productId;
        
        try (Jedis jedis = jedisPool.getResource()) {
            jedis.setex(key, 86400, String.valueOf(stock));  // 24小时过期
        }
    }
}
```

**优点**：
- 性能极好，单机可支撑 10 万+ QPS
- Lua 脚本保证原子性

**缺点**：
- 需要额外维护 Redis
- Redis 和数据库的一致性需要处理

### 1.5 消息队列异步方案

```java
/**
 * 消息队列异步扣减库存
 * 适用于超高并发场景
 */
public class MQInventoryService {
    
    /** RocketMQ 生产者 */
    private DefaultMQProducer producer;
    
    /** 库存服务 */
    private InventoryService inventoryService;
    
    /**
     * 发送扣减请求
     *
     * @param productId 商品ID
     * @param quantity 扣减数量
     * @param orderId 订单ID
     */
    public void sendDeductRequest(Long productId, Integer quantity, String orderId) {
        try {
            InventoryDeductMessage message = new InventoryDeductMessage();
            message.setProductId(productId);
            message.setQuantity(quantity);
            message.setOrderId(orderId);
            
            Message msg = new Message(
                "INVENTORY_DEDUCT_TOPIC",
                JSON.toJSONString(message).getBytes(RemotingHelper.DEFAULT_CHARSET)
            );
            
            producer.send(msg, new SendCallback() {
                @Override
                public void onSuccess(SendResult sendResult) {
                    log.info("库存扣减消息发送成功: {}", sendResult.getMsgId());
                }
                
                @Override
                public void onException(Throwable e) {
                    log.error("库存扣减消息发送失败", e);
                    // 降级处理：直接扣减数据库
                    inventoryService.deductStock(productId, quantity);
                }
            });
        } catch (Exception e) {
            log.error("发送消息异常", e);
            // 降级处理
            inventoryService.deductStock(productId, quantity);
        }
    }
    
    /**
     * 消费者：处理库存扣减
     */
    public class InventoryDeductConsumer implements MessageListenerConcurrently {
        
        @Override
        public ConsumeConcurrentlyStatus consumeMessage(
            List<MessageExt> msgs, 
            ConsumeConcurrentlyContext context
        ) {
            for (MessageExt msg : msgs) {
                try {
                    String body = new String(msg.getBody(), RemotingHelper.DEFAULT_CHARSET);
                    InventoryDeductMessage message = JSON.parseObject(body, InventoryDeductMessage.class);
                    
                    // 扣减数据库库存
                    boolean success = inventoryService.deductStock(
                        message.getProductId(), 
                        message.getQuantity()
                    );
                    
                    if (!success) {
                        // 库存不足，发送回滚消息
                        sendRollbackMessage(message);
                    }
                    
                } catch (Exception e) {
                    log.error("处理库存扣减消息失败", e);
                    return ConsumeConcurrentlyStatus.RECONSUME_LATER;
                }
            }
            return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
        }
    }
}
```

**优点**：
- 削峰填谷，保护数据库
- 异步处理，提高吞吐量

**缺点**：
- 实时性差
- 需要处理消息丢失、重复消费

## 二、超卖问题及解决方案

### 2.1 超卖原因

```
用户A 查询库存 = 1
用户B 查询库存 = 1（A 还未扣减）
用户A 扣减库存 → 成功（库存 = 0）
用户B 扣减库存 → 成功（库存 = -1）❌ 超卖！
```

### 2.2 解决方案

#### 方案一：数据库唯一约束

```sql
-- 创建库存表
CREATE TABLE inventory (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    product_id BIGINT NOT NULL,
    stock INT NOT NULL DEFAULT 0,
    version INT NOT NULL DEFAULT 0,
    UNIQUE KEY uk_product_id (product_id)
);

-- 扣减库存（保证不超卖）
UPDATE inventory 
SET stock = stock - 1, version = version + 1 
WHERE product_id = ? AND stock > 0;
```

**关键点**：`WHERE stock > 0` 保证库存不会变成负数。

#### 方案二：Redis 原子操作

```lua
-- Lua 脚本保证原子性
local stock = tonumber(redis.call('GET', KEYS[1]))
if stock == nil or stock < 1 then
    return 0  -- 库存不足
end
redis.call('DECR', KEYS[1])
return 1  -- 扣减成功
```

#### 方案三：分布式锁

```java
/**
 * 使用分布式锁防止超卖
 */
public class DistributedLockInventory {
    
    /** Redisson 客户端 */
    private RedissonClient redissonClient;
    
    /**
     * 扣减库存（分布式锁）
     *
     * @param productId 商品ID
     * @param quantity 扣减数量
     * @return 是否成功
     */
    public boolean deductStock(Long productId, Integer quantity) {
        String lockKey = "inventory:lock:" + productId;
        RLock lock = redissonClient.getLock(lockKey);
        
        try {
            // 尝试获取锁，最多等待 3 秒，锁自动释放 10 秒
            if (lock.tryLock(3, 10, TimeUnit.SECONDS)) {
                // 1. 查询当前库存
                Integer currentStock = getStockFromDB(productId);
                
                // 2. 校验库存
                if (currentStock < quantity) {
                    return false;
                }
                
                // 3. 扣减库存
                int rows = deductStockInDB(productId, quantity);
                return rows > 0;
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
        
        return false;
    }
}
```

## 三、高并发库存设计

### 3.1 秒杀场景架构

```
用户请求 → Nginx → 应用服务器 → Redis 预扣 → 消息队列 → 数据库
                ↓
            本地缓存（库存为0直接返回）
```

### 3.2 分层扣减策略

```java
/**
 * 分层扣减库存
 * 本地缓存 → Redis → 数据库
 */
public class LayeredInventoryService {
    
    /** 本地缓存（库存标记） */
    private Cache<Long, Boolean> stockCache = CacheBuilder.newBuilder()
        .maximumSize(10000)
        .expireAfterWrite(1, TimeUnit.SECONDS)
        .build();
    
    /** Redis 库存服务 */
    private RedisInventoryService redisInventoryService;
    
    /** 数据库库存服务 */
    private DBInventoryService dbInventoryService;
    
    /**
     * 扣减库存
     *
     * @param productId 商品ID
     * @param quantity 扣减数量
     * @return 是否成功
     */
    public boolean deductStock(Long productId, Integer quantity) {
        // 第一层：本地缓存快速失败
        Boolean hasStock = stockCache.getIfPresent(productId);
        if (hasStock != null && !hasStock) {
            return false;  // 本地缓存显示无库存
        }
        
        // 第二层：Redis 预扣
        Long result = redisInventoryService.deductStock(productId, quantity);
        if (result == 0) {
            stockCache.put(productId, false);  // 标记为无库存
            return false;
        }
        if (result == -1) {
            return false;  // 库存不存在
        }
        
        // 第三层：异步扣减数据库
        sendDeductMessage(productId, quantity);
        
        return true;
    }
}
```

### 4.3 库存预留与释放

```java
/**
 * 库存预留服务
 * 下单时预留库存，支付成功后扣减，超时释放
 */
public class InventoryReservationService {
    
    /**
     * 预留库存
     *
     * @param orderId 订单ID
     * @param productId 商品ID
     * @param quantity 数量
     * @return 预留ID
     */
    public String reserveStock(String orderId, Long productId, Integer quantity) {
        String reservationId = UUID.randomUUID().toString();
        
        // 1. 扣减可用库存
        boolean success = deductAvailableStock(productId, quantity);
        if (!success) {
            throw new BusinessException("库存不足");
        }
        
        // 2. 创建预留记录
        InventoryReservation reservation = new InventoryReservation();
        reservation.setReservationId(reservationId);
        reservation.setOrderId(orderId);
        reservation.setProductId(productId);
        reservation.setQuantity(quantity);
        reservation.setStatus(ReservationStatus.RESERVED);
        reservation.setExpireTime(LocalDateTime.now().plusMinutes(30));  // 30分钟过期
        
        reservationMapper.insert(reservation);
        
        // 3. 发送延迟消息，超时自动释放
        sendDelayMessage(reservationId, 30);
        
        return reservationId;
    }
    
    /**
     * 确认扣减（支付成功）
     *
     * @param reservationId 预留ID
     */
    public void confirmDeduction(String reservationId) {
        // 1. 查询预留记录
        InventoryReservation reservation = reservationMapper.selectByReservationId(reservationId);
        
        // 2. 更新状态为已扣减
        reservation.setStatus(ReservationStatus.CONFIRMED);
        reservationMapper.update(reservation);
        
        // 3. 扣减实际库存
        deductActualStock(reservation.getProductId(), reservation.getQuantity());
    }
    
    /**
     * 释放预留库存（超时或取消）
     *
     * @param reservationId 预留ID
     */
    public void releaseReservation(String reservationId) {
        // 1. 查询预留记录
        InventoryReservation reservation = reservationMapper.selectByReservationId(reservationId);
        
        // 2. 检查状态
        if (reservation.getStatus() != ReservationStatus.RESERVED) {
            return;  // 已确认或已释放
        }
        
        // 3. 更新状态为已释放
        reservation.setStatus(ReservationStatus.RELEASED);
        reservationMapper.update(reservation);
        
        // 4. 恢复可用库存
        increaseAvailableStock(reservation.getProductId(), reservation.getQuantity());
    }
}
```

## 五、库存一致性保证

### 5.1 Redis 与数据库一致性

```java
/**
 * 库存一致性服务
 * 保证 Redis 和数据库的库存一致
 */
public class InventoryConsistencyService {
    
    /**
     * 双写方案
     *
     * @param productId 商品ID
     * @param quantity 扣减数量
     */
    public void deductWithConsistency(Long productId, Integer quantity) {
        // 1. 先扣减 Redis
        Long result = redisInventoryService.deductStock(productId, quantity);
        if (result != 1) {
            throw new BusinessException("库存不足");
        }
        
        try {
            // 2. 再扣减数据库
            dbInventoryService.deductStock(productId, quantity);
        } catch (Exception e) {
            // 3. 数据库扣减失败，回滚 Redis
            redisInventoryService.increaseStock(productId, quantity);
            throw e;
        }
    }
    
    /**
     * 异步对账
     */
    @Scheduled(fixedRate = 60000)  // 每分钟执行
    public void reconcileInventory() {
        // 1. 查询所有商品库存
        List<Inventory> dbInventories = dbInventoryService.queryAllInventories();
        
        for (Inventory inventory : dbInventories) {
            // 2. 查询 Redis 库存
            Long redisStock = redisInventoryService.getStock(inventory.getProductId());
            
            // 3. 比较差异
            if (!inventory.getStock().equals(redisStock.intValue())) {
                log.warn("库存不一致: productId={}, dbStock={}, redisStock={}",
                    inventory.getProductId(), inventory.getStock(), redisStock);
                
                // 4. 以数据库为准，修复 Redis
                redisInventoryService.initStock(inventory.getProductId(), inventory.getStock());
            }
        }
    }
}
```

### 5.2 最终一致性方案

```java
/**
 * 最终一致性方案
 * 通过消息队列保证最终一致
 */
public class EventualConsistencyInventory {
    
    /**
     * 扣减库存
     *
     * @param productId 商品ID
     * @param quantity 扣减数量
     * @param orderId 订单ID
     */

        InventoryDeductEvent event = new InventoryDeductEvent();

        event.setQuantity(quantity);
        event.setOrderId(orderId);
        event.setEventId(UUID.randomUUID().toString());
        event.setTimestamp(System.currentTimeMillis());
        
        eventPublisher.publish(event);
    }
    
    /**
     * 事件处理器
     */
    @EventListener
    public void handleDeductEvent(InventoryDeductEvent event) {
        // 1. 幂等检查
        if (eventStore.exists(event.getEventId())) {
            return;
        }
        
        // 2. 扣减数据库库存
        dbInventoryService.deductStock(event.getProductId(), event.getQuantity());
        
        // 3. 记录事件
        eventStore.save(event);
        
        // 4. 更新 Redis
        redisInventoryService.decreaseStock(event.getProductId(), event.getQuantity());
    }
}
```

## 六、面试题

### 6.1 基础题

**Q1：库存扣减有哪些方案？各有什么优缺点？**

> **参考答案**：
> 主要有 5 种方案：
> 1. **悲观锁（SELECT ... FOR UPDATE）**：强一致性，但性能差，适合低并发
> 2. **乐观锁（version 字段）**：性能好，但高并发时失败率高
> 3. **Redis 预扣**：性能极好，但需要维护 Redis 一致性
> 4. **消息队列异步**：削峰能力强，但实时性差
> 5. **分布式锁**：强一致性，但性能中等
> 
> 选择建议：低并发用悲观锁，中等并发用乐观锁，高并发用 Redis 预扣 + 消息队列异步。

**Q2：什么是超卖？如何解决？**

> **参考答案**：
> 超卖是指库存扣减后变成负数，导致卖出超过实际库存的商品。
> 
> 解决方案：
> 1. **数据库约束**：`WHERE stock > 0` 保证不超卖
> 2. **Redis 原子操作**：Lua 脚本保证原子性
> 3. **分布式锁**：加锁扣减，但性能差
> 4. **唯一订单号**：防止重复扣减

**Q3：Redis 和数据库的库存如何保持一致？**

> **参考答案**：
> 1. **双写方案**：先写 Redis，再写数据库，失败回滚 Redis
> 2. **异步对账**：定时任务比较 Redis 和数据库，修复差异
> 3. **最终一致性**：通过消息队列，保证最终一致
> 4. **以数据库为准**：Redis 只做缓存，以数据库数据为准

### 6.2 进阶题

**Q4：秒杀场景下，如何设计库存系统？**

> **参考答案**：
> 1. **多级缓存**：本地缓存 → Redis → 数据库
> 2. **Redis 预扣**：先扣减 Redis，异步更新数据库
> 3. **消息队列**：削峰填谷，保护数据库
> 4. **库存预热**：系统启动时加载库存到 Redis
> 5. **快速失败**：库存为 0 时直接返回，不穿透到数据库
> 
> 架构：用户 → Nginx → 应用服务器 → Redis → MQ → 数据库

**Q5：分布式系统中，如何保证多个仓库的库存一致性？**

> **参考答案**：
> 1. **分布式事务**：使用 Seata、TCC 等方案
> 2. **最终一致性**：通过消息队列，最终达到一致
> 3. **补偿机制**：扣减失败时回滚其他仓库
> 4. **库存预留**：先预留，支付成功后确认扣减
> 5. **对账系统**：定时对账，修复差异

**Q6：库存预留和释放如何实现？**

> **参考答案**：
> 1. **预留**：下单时预留库存，创建预留记录，发送延迟消息
> 2. **确认**：支付成功后，更新状态为已扣减
> 3. **释放**：超时或取消时，恢复可用库存
> 4. **延迟队列**：使用 RocketMQ 延迟消息，30 分钟超时自动释放
> 5. **幂等性**：预留 ID 唯一，防止重复预留

### 6.3 场景题

**Q7：设计一个电商库存系统，支持高并发秒杀**

> **参考答案**：
> 
> **架构设计**：
> ```
> 用户 → CDN → Nginx → 应用服务器 → 本地缓存 → Redis → MQ → 数据库
> ```
> 
> **核心功能**：
> 1. **库存预热**：系统启动时加载库存到 Redis
> 2. **多级缓存**：本地缓存（库存标记）→ Redis → 数据库
> 3. **Redis 预扣**：Lua 脚本原子扣减
> 4. **消息队列**：异步扣减数据库
> 5. **库存预留**：下单预留，支付确认，超时释放
> 6. **对账系统**：定时对账，修复不一致
> 
> **关键点**：
> - 库存为 0 时快速失败
> - 防止超卖（数据库约束 + Redis 原子操作）
> - 防止重复扣减（订单号唯一）

**Q8：如何处理库存扣减失败的情况？**

> **参考答案**：
> 1. **重试机制**：乐观锁方案自动重试 3 次
> 2. **降级方案**：Redis 失败时直接扣减数据库
> 3. **回滚 Redis**：数据库失败时回滚 Redis 库存
> 4. **消息重试**：消息队列消费失败时重试
> 5. **人工介入**：记录异常日志，人工处理

```java
 * 资金归集（类似库存扣减）

     * 归集资金
     *

            return false;
        }

        accountService.addBalance(GROUP_ACCOUNT_ID, amount);
        
        // 5. 记录流水

    }
```
