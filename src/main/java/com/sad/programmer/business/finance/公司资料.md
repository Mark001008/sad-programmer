## 二、核心业务分析

### 2.1 业务范围（金融许可证核准）

```
┌─────────────────────────────────────────────────────────────┐
│                   中国电信财务公司业务范围                      │
├─────────────────────────────────────────────────────────────┤
│ 1. 对成员单位办理财务和融资顾问                                │
│ 2. 对成员单位办理信用鉴证及相关的咨询、代理业务                  │

└─────────────────────────────────────────────────────────────┘
```

### 2.2 核心业务模块详解

#### 2.2.1 资金归集业务

```
                    中国电信集团财务有限公司
                           │
            ┌──────────────┼──────────────┐
            │              │              │
       自动归集        手动归集        定向归集
            │              │              │
    ┌───────┴───────┐      │       ┌──────┴──────┐
    │               │      │       │             │
  日终归集      实时归集    按需    专项归集    应急归集
  (T+1清算)   (实时划转)  (审批)  (项目资金)  (流动性)
```

- **归集模式**：
  - **限额归集**：每日日终自动将成员单位账户余额超过保留限额的部分归集到财务公司主账户
  - **实时归集**：超过阈值的资金实时上划，适用于资金量大的省级公司
  - **定向归集**：针对特定项目资金（如基建投资、采购款）的专项归集
- **归集频率**：日终自动 + 实时触发（双模式并行）
- **成员单位账户**：在合作银行（工农中建交等）开立的账户通过银企直连接口进行资金划转

#### 2.2.2 内部结算业务

- **结算量**：日均结算笔数约 **5,000 - 20,000 笔**，日均结算金额约 **50 - 150 亿元**
- **结算类型**：
  - 内部转账结算（成员单位之间）
  - 代理收付款结算
  - 跨行代收代付
  - 工资代发（集团统一薪酬发放）
- **结算时效**：内部转账 T+0 实时到账，跨行结算 T+0/T+1

#### 2.2.3 信贷业务

| 业务类型 | 说明 |
|----------|------|
| **内部贷款** | 向成员单位发放短期流动资金贷款、中长期项目贷款 |
| **委托贷款** | 充当集团内资金中介，实现成员单位间资金融通 |
| **票据承兑** | 为成员单位开具银行承兑汇票和商业承兑汇票 |
| **票据贴现** | 成员单位持未到期票据向财务公司申请贴现 |
| **融资租赁** | 为成员单位提供通信设备、基础设施等融资租赁服务 |
| **保函业务** | 为成员单位提供投标保函、履约保函等 |

- **贷款规模估算**：集团内贷款余额约 **300 - 500 亿元**
- **票据业务量**：年票据承兑 + 贴现量约 **200 - 400 亿元**
- **信贷特点**：利率通常低于外部银行贷款利率（内部优惠利率），审批流程更灵活

#### 2.2.4 投资业务

- **投资范围**：受银保监会监管限制，主要投资于：
  - 国债、政策性金融债、地方政府债
  - 银行间市场同业存单
  - 货币市场基金
  - 银行理财（合规产品）
- **投资规模**：约 **200 - 400 亿元**
- **投资策略**：以流动性管理和稳健收益为核心，不追求高收益

#### 2.2.5 同业业务

- **同业拆借**：在银行间市场进行短期资金融通
- **同业存款**：在合作银行开立同业存款账户
- **业务目的**：流动性管理、头寸调剂

### 3.4 财务公司与银行的核心区别

| 维度 | 财务公司 | 银行 |
|------|----------|------|
| 服务范围 | 仅集团成员单位 | 全社会 |
| 牌照 | 非银行金融机构牌照 | 银行牌照 |
| 监管 | 金融监管总局非银部 | 金融监管总局银行部 |
| 资金来源 | 成员单位存款 | 全社会存款 |
| 核心职能 | 资金集中管理 | 信用中介 |

**集团为什么需要财务公司**：
- 资金归集：把分散在 200+ 成员单位的闲散资金集中起来，提高使用效率
- 内部结算：成员单位之间的交易通过财务公司内部转账，减少外部银行手续费
- 统一融资：集团统一对外融资，利率比单个成员单位更低
- 风险管控：集中监控资金流向，防范资金风险

## 四、技术栈选型背景

> 仅说明"为什么选这些技术"，不展开技术实现细节。

### 4.1 整体选型

| 组件 | 选型 | 选型核心原因 |
|------|------|-------------|
| **应用框架** | Spring Boot | Java 企业级事实标准，央企招标默认要求，生态成熟 |
| **服务治理** | Apache Dubbo | 二进制协议高性能，国产化偏好，内置服务治理 |
| **数据库** | OceanBase | Paxos 强一致（零数据丢失），MySQL 兼容零改造，信创国产化 |
| **ORM** | MyBatis | 与 OceanBase MySQL 模式配合，灵活 SQL 控制 |
| **缓存** | Redis | 高性能内存缓存，分布式锁，金融场景广泛验证 |
| **消息队列** | RocketMQ | 原生事务消息（金融核心需求），阿里金融级验证 |
| **任务调度** | XXL-JOB | 分片广播并行，可视化管理，轻量级部署 |

### 4.2 选型背后的行业驱动

1. **信创国产化**：央企信息系统国产化替代是政策要求，OceanBase（蚂蚁集团自研）、Dubbo（阿里开源）符合国产化方向
2. **金融级可靠性**：财务公司管理千亿级资金，数据一致性要求极高（RPO=0），这是选择 OceanBase 和 RocketMQ 事务消息的根本原因
3. **集团生态对齐**：中国电信集团 IT 体系以 Java/Spring 为主，技术栈选型需与集团生态兼容
4. **运维能力匹配**：团队规模有限（非互联网大厂），选择成熟、文档完善、社区活跃的技术栈降低运维风险

```
┌──────────────────────────────────────────────────────────────────┐
│                     监管合规要求                                  │
├──────────────────────────────────────────────────────────────────┤
```
